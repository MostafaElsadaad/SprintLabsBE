# Missions System
2026-10-04. Source: Jira NOX-103, children NOX-104–113. Backend scope only; NOX-118/119 Unity integration is separate.
Implement global missions for active authenticated B2C and B2B profiles: reusable templates and rewards, explicit UTC weekly/monthly/open activations, fixed plus stable weighted random assignments, server-only single/bulk facts, five generic progress modes, manual atomic XP/coins/immediate box rewards, and expiry with configurable auto-claim. Backend owns all progression and rewards.
Defaults: immutable published configuration; assignment stores rule/reward/box snapshots; game server supplies unique eventId per human event; reset safe to repeat and lazy expiry runs on player access. No client-authored mission facts. Explicit reset called by platform admin; no external scheduler provisioned. Timed periods use [startsAt, endsAt); late events cannot revive expired assignments; out-of-order events affecting ordered state rejected. Events can arrive before first lobby visit but must be within currently active activation and recorded before expiry. Event writes require canonical active user/profile, supplied match participant and community context checks.
Box catalog/inventory does not exist in base repository. Add only minimal weighted box contents, item catalog and player quantity persistence necessary for claims; no shop purchases/equipment API. Optional NOX-112 gets create-template/create-activation/list-preview endpoints; updates/deletes/reward CRUD are deferred because immutable configuration is sufficient for MVP. Seed endpoint is explicit admin invocation, never startup data mutation.
