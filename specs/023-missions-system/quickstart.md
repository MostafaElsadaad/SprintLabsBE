# Integration and verification
1. Review `MissionsSystem` source migration and migration.sql against development. It adds mission tables plus the minimal box catalog/inventory tables; it does not backfill/activate missions. Confirm no preexisting custom tables use these names. MySQL DDL can commit implicitly; take the normal database backup/schema review before migration. No live migration is applied by this task.
2. Build/test the solution. Source migrations must follow MatchAnswerOrdering. Existing API startup auto-migrates, so do not run it against an unintended database merely to inspect routes.
3. Configure the existing private GameServer credential in backend/server processes. Keep it out of Unity clients, source, Swagger URL/query strings and shared Postman exports.
4. On a disposable/development database, call POST `/api/v1/admin/missions/seed` as platform admin. It creates four demonstration templates, one box/item, a weekly fixed+random activation, monthly fixed activation and an open fixed activation. Repeating in the same period returns the same IDs. Seed item icon/prefab keys are demonstration keys; supply real item assets before production use.
5. GET `/Missions/me` with a real active player JWT. Four seed missions should appear. Repeat to verify stable IDs; use a second B2C/B2B player to verify isolation.
6. Submit trusted events with unique IDs: PowerupUsed with powerupKey=shield; ten CorrectAnswer events; three MatchWon with position=1; DiceRolled with diceValue=3 twice. If using a matchId, register the real match/roster first and provide matching community/timestamp context. Replay an event, then change its data with the same ID to verify 409.
7. Claim completed missions. Verify XP/level, Player.Gold and immediate Mission Hat inventory quantity; repeat box claim to confirm the same saved roll and no second grant. Claim another player's ID: 404. Player JWT against event route: 401. Community owner against reset: 403.
8. Test explicit ended activation in a disposable DB: incomplete expires, completed auto-claims when enabled, completed expires when disabled. Open periods remain. Run reset twice; second run has zero changes. No scheduler is provisioned; configure an authenticated recurring caller separately when needed.
9. Run optional MySQL concurrency fixtures using only `SPRINTLABS_MYSQL_TEST_CONNECTION` with a dedicated sprintlabs-test/compass-test database prefix and create/drop privileges. Fixtures create/drop unique test databases, never application databases. Exercise simultaneous claim, assignment, event retry and overlapping match XP/mission XP. SQLite tests are not proof of MySQL lock behavior.

Future decisions: immutable admin publication vs full edit/cancel APIs; UTC reset cadence and external scheduler; real box catalog/odds/assets; event delivery/retry/order guarantees for NOX-118; maximum active mission count and audit retention; whether a richer conditions language or full shop feature is needed. Configuration defaults are explicit in spec.md and api.md; no clarification is required to use the current MVP.
